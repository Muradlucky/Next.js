# Полный справочный каталог ECC (everything-claude-code) v2.2.3

**Что это.** ECC — открытый набор «надстроек» для Claude Code (а также Codex, Cursor, Gemini CLI, OpenCode и др.): готовые агенты-специалисты, навыки, команды, правила, автоматические хуки и подключения к сервисам. Здесь перечислено **всё** содержимое, чтобы вы могли выбрать нужное и не ставить лишнее.
**Для кого.** Для владельца агентства, не программиста: описания короткие, без жаргона. Большая часть набора написана для разработчиков; места, полезные бизнесу, помечены ★.
**Источник.** Репозиторий только читался (ничего не запускалось); описания навыков, агентов и команд взяты из их собственных заголовков (`description`) и переведены.

**Условные обозначения.**
- ★ — НЕ про программирование и может быть полезно бизнесу, агентству, исследованиям или построению системы ИИ-агентов.
- 🔎 — уже разбирается подробно в других файлах исследования (здесь только одна строка).
- Позиции внутри категории расставлены по алфавиту. Одна позиция живёт ровно в одной категории (даже если подходит к нескольким).

## 1. Агенты (71)

Агент — это отдельный «специалист» с узкой ролью, которого главный Claude вызывает для конкретной работы (ревью, планирование, проверка). Файлы лежат в `agents/`.

## 5. Хуки (hooks)

Хуки — это автоматические действия, которые срабатывают сами в определённые моменты: до/после использования инструмента, при отправке вашего запроса, в начале/конце сессии. Они ловят ошибки, ведут учёт, спасают контекст. Список взят из `hooks/hooks.json` и `hooks/hooks.metadata.json`: **27 записей**. Режим строгости переключается переменной `ECC_HOOK_PROFILE` (`minimal` / `standard` — по умолчанию / `strict`), отдельные хуки отключаются через `ECC_DISABLED_HOOKS`.

| Событие | Идентификатор | Что делает |
|---|---|---|
| Перед инструментом (PreToolUse) | `pre:bash:dispatcher` | Сводная проверка Bash-команд: блокирует запуск dev-сервера вне tmux, напоминает про tmux и про просмотр правок перед `git push`, перед `git commit` проверяет качество (линт, формат сообщения, забытые `console.log`/`debugger`/секреты). |
| Перед инструментом | `pre:powershell:gateguard-fact-force` | То же «требование фактов» (GateGuard 🔎) для опасных команд PowerShell. |
| Перед инструментом | `pre:write:doc-file-warning` | Предупреждает, если создаётся «лишний» .md/.txt-файл (не блокирует). |
| Перед инструментом | `pre:edit-write:suggest-compact` | Примерно каждые 50 вызовов предлагает вручную сжать контекст (`/compact`) — идея strategic-compact 🔎. |
| Перед инструментом | `pre:observe:continuous-learning` | Записывает наблюдения о действиях агента для самообучения (continuous-learning 🔎). |
| Перед инструментом | `pre:governance-capture` | Фиксирует события управления: секреты, нарушения политик, запросы одобрения. Включается `ECC_GOVERNANCE_CAPTURE=1`. |
| Перед инструментом | `pre:config-protection` | Запрещает править конфиги линтера и форматтера — агент должен чинить код, а не ослаблять правила. |
| Перед инструментом | `pre:mcp-health-check` | Перед вызовом внешнего сервиса (MCP) проверяет, что он жив, и блокирует вызовы к «упавшим». |
| Перед инструментом | `pre:edit-write:gateguard-fact-force` | GateGuard 🔎: не даёт первую правку файла, пока агент не предъявит конкретные факты (кто импортирует файл, какие данные, дословная просьба пользователя); чувствительные файлы (секреты, авторизация, платежи, миграции, CI) — всегда. |

Дополнительно в репозитории есть:
- `hooks/codex-hooks.json`, `hooks/qoder-hooks.json` — те же хуки в формате Codex и Qoder;
- `hooks/memory-persistence/` — описание цикла «сохранение памяти между сессиями»;
- `hooks/hermes/` — два защитных хука для Hermes (защита конфигов, предупреждение о console.log);
- в `scripts/hooks/` лежат реализации и несколько необязательных: блок `git --no-verify` (`block-no-verify.js`), монитор заполнения контекста и статусная строка (`ecc-context-monitor.js`, `ecc-statusline.js`), опциональный монитор безопасности `insaits-security-monitor.py`.
- Правила hookify (`/hookify`, `hookify-rules`) позволяют самому написать новое «запрещающее» правило обычным текстом; файлы правил из git по умолчанию **не** активируются — это защита от чужих инструкций в репозитории.

## 9. Неочевидные находки

Двадцать позиций, которых нет в списке 🔎, но которые могут пригодиться владельцу агентства, строящему систему ИИ-агентов.

1. **`counterparty-channel-discipline` (навык).** Правила поведения агента в общих чатах с клиентами и подрядчиками: кто «свой», кто внешний, когда молчать, чтобы не выдать внутренние следы и не написать лишнего. Ровно то, что нужно, когда агент сидит в клиентском Slack/Telegram.
2. **`master-agreement-generator` + `esign-field-placement` (навыки).** Собирают черновики типовых договоров (NDA, рамочные, реферальные) из одного шаблона и таблички данных контрагента и готовят расстановку полей подписи в сервисе электронной подписи. Всегда пометка «ЧЕРНОВИК», отправку решает человек.
3. **`agent-payment-x402` + `integrations/aura`.** Агент может платить за API по протоколу x402 с лимитами на задачу, а AURA — перед платежом или передачей работы проверяет репутацию контрагента-агента одним запросом. Заготовка для «экономики агентов».
4. **`data-scraper-agent` (навык).** Строит агента, который по расписанию собирает данные с любого публичного источника (вакансии, цены, новости, объявления), обогащает бесплатной моделью и пишет в Notion/Sheets. Мониторинг конкурентов и рынка почти без затрат.
5. **`regex-vs-llm-structured-text` (навык).** Как разбирать счета, квитанции и формы: 95% дешёвыми правилами, а ИИ только на сомнительное. Снижает цену обработки документов в разы.
6. **`taste-distillation`, `taste-application`, `tasteforge-video` (навыки).** Из набора эталонных роликов «снимают» стиль (цветокоррекция, ритм монтажа) в пакет и потом генерируют новое видео в этом же стиле. Фирменный видеостиль клиента на потоке.
7. **`videodb`, `video-editing`, `fal-ai-media` (навыки).** Поиск по видео по словам и сценам, монтаж с ИИ и генерация картинок/видео/озвучки. Готовый конвейер для контент-студии.
8. **`brand-discovery` (навык).** Возобновляемое интервью о бренде на 8 модулей (цель, позиционирование, аудитория, голос…) — готовая методика брифинга клиента, дающая материал для `brand-voice`.
9. **Агенты `marketing-agent`, `seo-specialist` + навыки `seo`, `x-api`.** Агент-маркетолог (кампании, лендинги, письма, реклама, сценарии) и SEO-специалист — единственные нетехнические агенты из 71, их можно вызывать как «сотрудников» напрямую.
10. **`gan-style-harness` + агенты `gan-planner/generator/evaluator` + `loop-design-check`.** Паттерн «исполнитель и придирчивый оценщик по рубрике» плюс чек-лист, как не создать цикл, который вечно крутится или обманывает проверку. Применим не только к коду — к любому контенту с критериями.
11. **`agent-architecture-audit` + `agent-introspection-debugging`.** Диагностика собственной агентной системы по 12 слоям (деградация обвязки, «грязная» память, скрытые циклы починки) и структурный разбор сбоя агента. Нужны, когда система «странно себя ведёт».
12. **`dev-team` (навык).** Одна сессия, где отвечают сразу роли PM, архитектор, разработчик, QA — дешёвая замена совещанию по идее или решению.
13. **`plan-canvas` (навык и команда).** План открывается в браузере: вы или клиент комментируете элементы и нажимаете «одобрить», агент продолжает. Удобный канал согласования для нетехнического человека.
14. **`delivery-gate` (навык-хук).** Не даёт агенту объявить работу завершённой, пока не пройдены проверки; ловит фразы-«отговорки» и просроченные журналы обучения. Страховка от «готово!» без проверки.
15. **`automation-audit-ops`, `workspace-surface-audit`, `config-gc`.** Три инструмента «инвентаризации»: что из автоматизаций, коннекторов и MCP живо, сломано или дублируется, и уборка устаревшего в конфигурации. Нужны, когда агентов и подключений станет много.
16. **MCP `nexus`.** Локальный прокси, который выбирает самую дешёвую способную модель, ведёт статистику экономии и **маскирует секреты и персональные данные перед отправкой наружу** — важно, если агенты работают с данными клиентов.
17. **MCP-память: `longhand`, `omega-memory`, `ecc-memory-vault`, `memxus`.** Четыре разных подхода (дословный архив сессий, семантическая память с графом знаний, общее локальное хранилище для разных агентов, облачная общая память). Выбирайте осознанно; у `memxus` в описании прямо предупреждение об «отравлении памяти».
18. **Профиль контекста `lean@1` (`manifests/context-profiles/`).** При 311 навыках контекст раздувается; предложенный «тонкий» профиль держит постоянно загруженными только 3 навыка, остальное подгружает по запросу в бюджете 8000 токенов (пока это проект, а не включённый режим). Идея прямо против лишних расходов.
19. **Научный и расследовательский пакет: `scientific-db-pubmed-database`, `scientific-db-uspto-database`, `scientific-pkg-gget`, `scientific-thinking-literature-review`, `scientific-thinking-scholar-evaluation`, `osint-investigation`.** Литобзоры по PubMed, патенты и товарные знаки США, оценка научных работ, OSINT — основа для исследовательских услуг и due diligence.
20. **Операционные пакеты: `customer-billing-ops`, `finance-billing-ops`, `google-workspace-ops`, `unified-notifications-ops` и «цепочка поставок» (8 навыков: перевозчики, таможня, энергия, спрос и запасы, нештатные ситуации, производство, качество, возвраты).** Готовые инструкции для биллинга (Stripe), Google Drive/Docs/Sheets, маршрутизации уведомлений и для клиентов из e-commerce и логистики.
