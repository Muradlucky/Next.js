## VoltAgent: что внутри бизнес-агентов

**Шаблонные агенты** (13 из 18: business-analyst, project-manager, product-manager, content-marketer, ux-researcher, scrum-master и др., по ~286 строк):

- Основная часть текста — списки ключевых слов («Stakeholder interviews», «BPMN notation»…), а не методика.
- Первый шаг: «Query context manager». Такого агента в наборе нет, и JSON-«протокол общения» ни к чему не подключён.
- В примере итогового отчёта зашиты выдуманные цифры («87 requirements… $2.3M annual savings»). Модель может воспроизвести этот образец и выдать вымышленные метрики.
- У части агентов зашита `model: haiku` (project-manager, content-marketer), то есть они будут работать на более слабой модели, чем основная сессия.

**Короткие агенты** (assumption-mapping, growth-loops, backlog-grooming, telegram-ads-analyst, content-quality-editor, 55–90 строк) описывают конкретную методику, формат результата и критерии. Ссылок на несуществующего агента и выдуманных цифр в них нет.

**Безопасность.** В агентах исполняемого кода нет. `install-agents.sh` только скачивает `.md` с GitHub через `curl`. В репозитории лежит `.claude/settings.local.json` с разрешением `Bash(python3:*)`. Если открыть клон этого каталога как проект Claude Code, это разрешение начнёт действовать, поэтому копировать нужно отдельные файлы агентов, а не весь репозиторий.

**Совместимость с Codex.** Codex не читает `.claude/agents/*.md`. Короткий агент переносится в Codex-навык почти без правок: тело файла становится `SKILL.md` с полями `name` и `description`. Шаблонные агенты переносить нет смысла.

## Что подключено в этом репозитории

`.claude/agents/assumption-mapping.md` — один агент для пробы, скопирован из VoltAgent с указанием источника. Единственная правка: из `tools` убраны `Write` и `Edit`, потому что агенту нужно только анализировать и выдавать таблицу.

Как проверить: дать ему реальную продуктовую идею или фичу («найди рискованные допущения в …») и сравнить результат с ответом без агента на тот же запрос.
