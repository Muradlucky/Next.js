# 07. Проекты и подходы других авторов, близкие к ECC

Дата сбора: 28.10.2026. Читатель: владелец агентства, не программист; строит систему агентов на облачных сессиях Claude Code (оркестратор + дочерние сессии + задачи по расписанию), база знаний в Google Docs.

## Как читать этот документ

- **Звёзды и версии** взяты со страниц GitHub, которые я открывал сегодня, и указаны «по данным на 28.10.2026». Страницы пересказывались автоматически, так что цифры ориентировочные. Звёзды в таких списках быстро растут и бывают раздуты, поэтому по ним нельзя судить о качестве.
- **Пометка «только поиск»** значит, что проект найден через поиск и я не открывал его страницу. Описание там краткое и менее надёжное.
- **Пометка «репозиторий существует»** значит, что я проверил его командой `git ls-remote`, но README не читал.
- **Колонка «облако»** отвечает на вопрос: будет ли это работать в облачной сессии Claude Code, когда твой компьютер выключен. Оценку я делал по описаниям установки и требованиям. Явно написанного ответа в источниках почти нигде нет, поэтому «похоже, что да» и «похоже, что нет» это мой вывод, а не факт.
- **Что известно про облачные сессии** (из официальной документации):
  - они работают на серверах Anthropic и продолжаются при выключенном ноутбуке;
  - они **не читают** твой локальный `~/.claude/settings.json`;
  - команды вроде `/plugin` в облаке недоступны;
  - субагенты из папки `.claude/agents/` репозитория подхватываются;
  - у обычной облачной сессии сеть по умолчанию ограничена;
  - в «проекте» (Projects) потоки подхватывают только `CLAUDE.md` репозитория, но **не** его skills, `.claude/settings.json` и `.mcp.json`.
  - Поэтому всё, что требует tmux, локальной программы или локального процесса (MCP-сервер через `npx`/`uvx`), в облаке заработает только при отдельной настройке или не заработает вообще.

### Точка отсчёта: что такое ECC (для сравнения)

По странице репозитория (28.10.2026): ECC это набор для Claude Code, Codex, Cursor, OpenCode и др. Внутри 71 субагент, 311 навыков (skills), 97 слэш-команд, хуки (автоматические проверки на событиях), память сессий, «инстинкты» (повторяющиеся паттерны с оценкой уверенности), оркестрация, управление git-ветками для параллельной работы и сканер конфигурации AgentShield. Около 291 тыс. звёзд. На странице сказано, что за пределами Claude Code совместимость функций не гарантируется.

## Топ-10 для спринтов на изучение

Порядок: от самого полезного для вашей схемы (облачные сессии + расписание + Google Docs).

1. **Projects и cloud scheduled tasks (официальная документация Anthropic).** Это встроенная версия вашей схемы «оркестратор + дочерние сессии + расписание». Вынести: что именно общее у потоков (инструкция проекта и память), что **не** передаётся (навыки и настройки репозитория), какие у этого лимиты и цена. Начните с сравнения «ваша самодельная схема против Projects».
2. **«How we built our multi-agent research system» (Anthropic).** Вынести: как писать задание субагенту (цель, формат ответа, инструменты), правила «сколько усилий на запрос», и честное предупреждение про стоимость (многоагентные запуски примерно в 15 раз дороже чата, поэтому только для задач с высокой ценностью).
3. **«Effective harnesses for long-running agents» (Anthropic).** Вынести: «список функций в JSON + файл прогресса + git» как способ передавать работу между сессиями, у которых нет памяти. Это прямо ложится на дочерние сессии и расписание.
4. **«Demystifying evals for AI agents» + promptfoo.** Вынести: старт с 20–50 задач из реальных сбоев, оценка результата, а не пути; различие «проверка возможностей» и «проверка, что не сломалось». Promptfoo как первый инструмент, если дойдёте до автоматических прогонов.
5. **Superpowers (obra).** Вынести: цикл «уточнить → дизайн → план → свежий субагент на задачу → проверка» и привычку писать навыки как короткие инструкции. Смотреть как методику, а не как продукт.
6. **Beads и Gas Town (Yegge).** Вынести: «Мэр» (один главный разговор) + журнал задач вне контекста. Gas Town сам не берите (tmux, сложная установка, у автора по вторичным сведениям не сложилось), берите идею «журнал задач, который переживает сессии».
7. **CCPM (automazeio).** Вынести: путь «ТЗ → эпик → задачи → GitHub Issues → параллельная работа → отчёт о статусе». Это самый простой по требованиям (`git` + `gh`) пример оркестрации через задачи, подходящий для облака.
8. **LLM Council (Karpathy) + claude-council + «спор гипотез» из документации agent teams.** Вынести: схему «независимые мнения → анонимная рецензия → итог председателя» и то, как её сделать из субагентов в одной подписке, для стратегических решений агентства.
9. **basic-memory и шаблоны журнала решений.** Вынести: формат «заметка = факты + решения + ссылки», читаемый и человеком, и агентом; перенести этот формат в структуру Google Docs (журнал решений: дата, решение, почему, влияние).
10. **Marketing Skills (coreyhaines31) + knowledge-work-plugins (Anthropic) + contains-studio/agents.** Вынести: готовые формулировки навыков для лидов, исследования рынка, контента; посмотреть, как разбиты роли «студии» по отделам. Это самое быстрое прикладное улучшение для агентства.

**Кандидаты «на потом» (11–14):** SkillOpt (самообучение с отложенной проверкой, пригодится, когда будут накоплены навыки и тесты); BMAD Method (документы-артефакты и модуль BMad Loop); Graphiti (идея «сроков действия фактов»); Archon (рабочий процесс YAML с точками «жду решения человека»).

## Вывод для плана

- Для вашей схемы важнее **методики**, чем «агентные ОС»: многие популярные проекты (Ruflo, Gas Town, Claude Squad, OMC) рассчитаны на запуск на вашем компьютере (tmux, локальные базы, MCP-серверы через `npx`) и в облачных сессиях не заработают без доработок.
- Всё, что состоит из текстовых файлов (навыки, субагенты, шаблоны журналов), можно положить в репозиторий (`.claude/agents/`, `.claude/skills/`, `CLAUDE.md`), и оно будет работать в облаке. Исключение: внутри «проекта» навыки репозитория не подхватываются, их нужно подключать иначе (см. раздел «Get skills, plugins, connectors, and tools into threads» в документации Projects; эту часть страницы я не читал).
- **Безопасность:** многие плагины работают с правами вашего аккаунта и не изолированы (Ruflo предупреждает об этом прямо; у VoltAgent написано, что субагенты не аудированы). Перед установкой чужого навыка читайте его текст.
